## 修复：前端未真正入库（gitlink 未摘除）

**问题确认（TARO 指出，属实）**：提交 `2a7373c` 只装进了后端改动 + workflow + 删 `.gitmodules`，但 `assets` 在索引里仍是 `160000 commit 19da0fe`（gitlink），前端 803 个源文件一个都没进提交。

**假象成因**：gitlink 让 git 把 `assets/` 当单一条目、根本不看内部，所以 `git status` 显示 "working tree clean" —— 看着像干净，实则前端全被隐身。加上 `git show 2a7373c:assets/src/api/dashboard.ts` 报 "exists on disk, but not in"，才定位到。

**根因复盘**：我上次做 `git rm --cached assets` + `git add assets/` 后没有立刻 commit，中间被自动提交流程抓走了"删 .gitmodules"这一半，摘 gitlink 那一半丢失。

**教训：改索引结构必须当场 commit，不能只暂存**。

**修复（已推送 3f0035a）**
```
git rm --cached assets        # 摘 gitlink
git add assets/               # 1293 个文件
git commit + push
```
远端验证：`git ls-tree origin/... assets` = `040000 tree f8e5a598`（不再是 160000 commit），1293 个前端文件在库，3 个关键改动文件 ✓。

**另一个坑：git push 必须显式配代理**
- 沙箱有 `HTTPS_PROXY=http://127.0.0.1:61015`，但 git（LibreSSL）不读该环境变量，报 `SSL_ERROR_SYSCALL`
- `git config http.proxy` + `https.proxy` 配上后一次推送成功
- github.com 出网间歇性不通（走代理/直连都可能超时），失败先重试再排查
